# KOT Digital

پایهٔ محیط توسعه و آزمایش اتصال‌های سایت‌ساز کوت دیجیتال.

این مخزن شامل نسخهٔ اولیهٔ کارخانهٔ سایت‌سازی و محیط آزمایش اتصال است. تولید سایت از قالب انجام می‌شود و به هوش مصنوعی یا سرویس پرداخت متصل نیست.

## نسخهٔ میزبانی‌شده

منبع برنامه در `worker/` است. دستور `node scripts/build.mjs` یک Worker مستقل در `dist/server/index.js` می‌سازد؛ بستهٔ خارجی لازم نیست. شناسهٔ محیط در `.openai/hosting.json` قرار دارد. ریشهٔ سایت پنل ساخت پروژه است؛ آزمون اتصال در `/sandbox` و مسیرهای `/health` و `/mock/webhook` باقی مانده است.

بررسی نسخهٔ میزبانی با Node.js 24:

```sh
node scripts/build.mjs
node --test scripts/*.test.mjs
```

برای انتشار، همین commit باید به مخزن منبع اختصاصی Sites ارسال و سپس نسخهٔ آن منتشر شود. ارسال به GitHub به‌تنهایی انتشار Sites را انجام نمی‌دهد. انتشار اولیه با دسترسی خصوصی انجام می‌شود؛ این موضوع مانع استفادهٔ سرویس‌های بیرونی بدون احراز هویت مناسب خواهد بود.

## اجرای محلی

پیش‌نیاز: Python 3.12. نصب بستهٔ اضافی لازم نیست.

```sh
python scripts/check.py
python scripts/sandbox.py
```

بررسی سلامت: `http://127.0.0.1:8000/health`

وب‌هوک آزمایشی:

```sh
curl -X POST http://127.0.0.1:8000/mock/webhook \
  -H 'Content-Type: application/json' \
  -d '{"test":true}'
```

## محیط قابل بازسازی

پیکربندی Dev Container در مخزن قرار دارد. در VS Code با افزونهٔ Dev Containers یا در GitHub Codespaces می‌توان آن را باز کرد. هنگام ساخت محیط، بررسی‌ها اجرا می‌شوند؛ برای شروع سرویس دستور اجرای محلی بالا را بزنید. نمایش پورت را خصوصی نگه دارید.

مخزن کد با محیط همیشه‌روشن تفاوت دارد. محیط Codespaces ممکن است متوقف شود و مشمول سهمیه و هزینهٔ حساب است. این مخزن به‌تنهایی آدرس دائمی یا میزبانی رایگان تضمین‌شده ایجاد نمی‌کند.

## اتصال واقعی و نگهداری

- کلید و رمز را در کد یا مخزن قرار ندهید؛ از تنظیمات امن میزبان استفاده کنید.
- برای آزمایش فقط داده و حساب آزمایشی به کار ببرید.
- پس از مشخص شدن میزبان، محیط staging با آدرس ثابت، دادهٔ جدا و روش بازگشت نسخه پیکربندی می‌شود.
- مسیر `/mock/webhook` برای آزمون پذیرش JSON است؛ احراز هویت یا اعتبارسنجی امضای سرویس واقعی ندارد و برای انتشار عمومی آماده نیست.
- بررسی خودکار GitHub Actions برای هر push و pull request تعریف شده است؛ اجرای آن به مجوز و سهمیهٔ حساب بستگی دارد.

## امکانات نسخهٔ اولیهٔ کارخانه

- سه قالب فارسی: خدماتی، نمونه‌کار و رستوران؛ خروجی مستقل HTML واکنش‌گرا
- ویرایش متن و رنگ، پیش‌نمایش، دانلود سایت و پشتیبان/بازیابی JSON
- ایجاد، بازیابی، ویرایش و حذف پروژه با کنترل تداخل ویرایش
- ذخیرهٔ سروری با binding منطقی `DB` و جدول `projects`؛ وضعیت واقعی از `/api/status`
- پنل فقط برای مالک و در محیط خصوصی قابل استفاده است؛ جداسازی مشتریان چندکاربره پیاده نشده است

فایل `drizzle/0000_projects.sql` فقط ساختار جدول را ایجاد می‌کند. باید در انتشار توسط میزبان اعمال شود. کد در زمان درخواست جدول نمی‌سازد. binding و جدول در نسخهٔ ۲ از طریق ابزار خواندن پایگاه داده و درخواست HTTP احرازشده بررسی شده‌اند. آزمون محلی نیز با SQLite واقعی اجرا می‌شود.

## محدودهٔ انتشار

نسخهٔ ۲ کارخانه به‌صورت خصوصی منتشر شده است: https://kot-digital-sandbox.kotpizza14.chatgpt.site . ایجاد جدول `projects` در binding `DB` و آزمون زندهٔ ایجاد، فهرست، بازیابی، ویرایش و حذف پروژه تأیید شده است. دادهٔ ساختگی آزمون پس از بررسی حذف شد. گزارش در `VERIFICATION.md` قرار دارد. دانلود HTML با انتشار عمومی سایت مشتری تفاوت دارد. دامنهٔ اختصاصی، انتشار خودکار سایت مشتری، حساب مشتری و نقش‌ها، پرداخت، فرم پیام و اتصال هوش مصنوعی هنوز پیاده‌سازی نشده‌اند.

هیچ تضمین هزینهٔ صفر برای استفادهٔ نامحدود از میزبانی یا ذخیره‌سازی داده نشده است. خرید و سرویس پولی تنظیم نشده است.
