# KOT Digital

پایهٔ محیط توسعه و آزمایش اتصال‌های سایت‌ساز کوت دیجیتال.

این مخزن فعلاً شامل سایت‌ساز کامل یا اتصال به سرویس واقعی نیست. سرویس آزمایشی داده‌ای ذخیره نمی‌کند و اتصال خارجی انجام نمی‌دهد.

## نسخهٔ میزبانی‌شده

ورودی سازگار با Sites در `dist/server/index.js` قرار دارد؛ این فایل منبع مستقیم Worker است و به مرحلهٔ build یا بستهٔ خارجی نیاز ندارد. شناسهٔ محیط در `.openai/hosting.json` ذخیره شده است. مسیرهای `/health` و `/mock/webhook` و صفحهٔ فارسی آزمون در این نسخه موجودند. سرویس Python پایین برای توسعهٔ محلی نگهداری شده است.

بررسی نسخهٔ میزبانی با Node.js 24:

```sh
node --test scripts/worker.test.mjs
```

برای انتشار، همین commit باید به مخزن منبع اختصاصی Sites ارسال و سپس نسخهٔ آن منتشر شود. ارسال به GitHub به‌تنهایی انتشار Sites را انجام نمی‌دهد. انتشار اولیه با دسترسی خصوصی انجام می‌شود؛ این موضوع مانع استفادهٔ سرویس‌های بیرونی بدون احراز هویت مناسب خواهد بود.

## اجرای محلی

پیش‌نیاز: Python 3.12. نصب بستهٔ اضافی لازم نیست.

```sh
python scripts/check.py
python scripts/sandbox.py
```

بررسی سلامت: `http://127.0.0.1:8000/health`

وب‌هوک آزمایشی:

```sh
curl -X POST http://127.0.0.1:8000/mock/webhook \
  -H 'Content-Type: application/json' \
  -d '{"test":true}'
```

## محیط قابل بازسازی

پیکربندی Dev Container در مخزن قرار دارد. در VS Code با افزونهٔ Dev Containers یا در GitHub Codespaces می‌توان آن را باز کرد. هنگام ساخت محیط، بررسی‌ها اجرا می‌شوند؛ برای شروع سرویس دستور اجرای محلی بالا را بزنید. نمایش پورت را خصوصی نگه دارید.

مخزن کد با محیط همیشه‌روشن تفاوت دارد. محیط Codespaces ممکن است متوقف شود و مشمول سهمیه و هزینهٔ حساب است. این مخزن به‌تنهایی آدرس دائمی یا میزبانی رایگان تضمین‌شده ایجاد نمی‌کند.

## اتصال واقعی و نگهداری

- کلید و رمز را در کد یا مخزن قرار ندهید؛ از تنظیمات امن میزبان استفاده کنید.
- برای آزمایش فقط داده و حساب آزمایشی به کار ببرید.
- پس از مشخص شدن میزبان، محیط staging با آدرس ثابت، دادهٔ جدا و روش بازگشت نسخه پیکربندی می‌شود.
- مسیر `/mock/webhook` برای آزمون پذیرش JSON است؛ احراز هویت یا اعتبارسنجی امضای سرویس واقعی ندارد و برای انتشار عمومی آماده نیست.
- بررسی خودکار GitHub Actions برای هر push و pull request تعریف شده است؛ اجرای آن به مجوز و سهمیهٔ حساب بستگی دارد.
